# Arda

A landing page for **Arda** — original songs in J.R.R. Tolkien's **Sindarin**,
written in the **Tengwar** script with English translations. One atmospheric
scrolling page whose centrepiece is a synced-lyrics "stage" that lights each
line as the song reaches it. Three mood themes (Twilight Gold · Moonlit Silver ·
Ember / Mourning).

Standalone, vanilla HTML/CSS/JS — **no framework and no build step to run.**

## Run it

Serve the folder over http (so synced `.lrc` files can load):

```bash
node scripts/dev-server.mjs
# open http://127.0.0.1:8777  (pass a port, or 0 for any free one)
```

Use this server rather than `python3 -m http.server`: it answers HTTP Range
requests like GitHub Pages does, and without them browsers cannot seek the
audio, so share links (`#t=`), the scrubber and click-to-seek on lyric lines
would not work locally.

## Tests

Node 24 runs the player regression tests against a simulated DOM and audio
transport. These are development dependencies only; the published site still
has no runtime dependencies or build step.

```bash
npm ci
npm test
```

`index.html` loads the CSS, the scripts and (through `app.js`) the `.lrc`
files with a `?v=` content hash, so browsers never keep a stale copy. After
editing `assets/`, `data/` or `lyrics/*.lrc`, refresh the hashes (the tests
fail until you do):

```bash
node scripts/stamp-versions.mjs
```

The deployment workflow runs the suite before publishing and includes only
`index.html`, `CNAME`, `LICENSE`, `assets/`, `audio/`, `data/` and
`lyrics/*.lrc` in the site artifact.

## Structure

```
index.html            markup shell (hero, stage, archive, colophon)
assets/app.css        three themes + all components
assets/app.js         player, LRC sync, Media Session, share links, themes, archive, hero motes
assets/fonts/         Tengwar Annatar (glaem-unicode .ttf)
data/songs.js         canonical lyrics: Sindarin + English per line  ← edit here
data/tengwar.js       generated Tengwar per line (do not hand-edit)
audio/                lossless FLAC + MP3 fallback per song
lyrics/               drop synced .lrc files here (see lyrics/README.md)
songs/                un-mastered WAV sources (git-ignored; no script uses them)
scripts/              one-time asset generators
docs/superpowers/specs/  the design spec
```

## Regenerating assets

The scripts only need to run when the source material changes; the site itself
needs none of them.

**Audio** — each song ships as lossless FLAC with an MP3 fallback;
`assets/app.js` plays the FLAC wherever `canPlayType("audio/flac")` says the
browser can (and falls back to the MP3 if the FLAC fails to load). The FLACs
are the mastered tracks committed as-is and are the source for everything
else: the script regenerates each `audio/<id>.mp3` from `audio/<id>.flac`
(never from the un-mastered WAVs in `songs/`):

```bash
bash scripts/transcode-audio.sh
```

**Lyric sheets** — after editing `data/songs.js`, refresh the plain-text sheets
in `lyrics/` that the lyrics-sync tool consumes (see `lyrics/README.md`):

```bash
node scripts/build-lyrics-txt.mjs
```

**Tengwar** — after editing `data/songs.js`, regenerate the script:

```bash
node scripts/transcribe-tengwar.mjs
```

This drives [Glǽmscribe](https://github.com/BenTalagan/glaemscribe) in the
*Sindarin — Tengwar (general use)* mode and writes `data/tengwar.js`. The engine
is AGPL and is used **only as a build tool** (vendored under `.tooling/`,
git-ignored); none of it ships with the site. Set `GLAEMSCRIBE_JS` to point at a
different engine checkout. Eyeball new lines against
[Tecendil](https://www.tecendil.com) (Sindarin mode) — mismatches are a one-line
fix in `data/songs.js`, then re-run.

## Deploy

Pushes to `main` deploy automatically: `.github/workflows/deploy-pages.yml`
publishes the site to GitHub Pages at [lind.arda.tr](https://lind.arda.tr)
(`CNAME` lives in the repo root). Pages serves the uploaded artifact as-is,
without Jekyll, so the root `.nojekyll` is not needed and is not published
(`actions/upload-pages-artifact` leaves dotfiles out). The workflow ships the static
site only — `docs/` and `scripts/` are excluded from the artifact, and
`songs/*.wav` and `.tooling/` are git-ignored, so none of it ever ships.
